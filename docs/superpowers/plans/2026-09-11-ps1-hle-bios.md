# PS1 HLE BIOS Modularization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract the existing JoJo-specific PS1 BIOS HLE semantics and state from `Ps1BootRuntime` into a focused `Ps1HleBios` component without changing guest-visible behavior, strict unsupported-frontier behavior, or MAX³ diagnostic semantics.

**Architecture:** `Ps1BootRuntime` remains the execution/reporting orchestrator and detects A0/B0/C0 BIOS vectors. It delegates production BIOS semantics to `Ps1HleBios`, which owns the existing HLE state and returns only `handled` or `unimplemented`; diagnostic fallback remains runtime-owned and MAX³-only. Runtime state hashing incorporates the HLE component hash rather than re-hashing individual BIOS fields.

**Tech Stack:** C++20, CMake 3.20+, CTest, existing synthetic PS-X EXE/MIPS test fixtures, MSVC/Linux CI.

**Spec:** `docs/superpowers/specs/2026-09-11-ps1-hle-bios-design.md`

## Global Constraints

- No proprietary PlayStation BIOS image is required, embedded, downloaded, committed, or distributed.
- HLE is JoJo-specific and implements only services already proven necessary by the supported startup/runtime path in this refactor.
- Unknown BIOS calls remain explicit unsupported frontiers and must never be silently treated as production success.
- `Ps1BootRuntime::run()` remains strict and returns `Ps1BootStopReason::bios_call_unimplemented` for unsupported BIOS calls.
- MAX³ fallback policies remain diagnostic-only and stay outside production HLE semantics.
- No game payload, RAM dump, BIOS ROM content, or proprietary data is serialized.
- MAX³ diagnostic deduplication remains deterministic.
- Existing `Ps1BootRuntime` HLE inspection accessors remain source-compatible.
- RED -> GREEN TDD is mandatory; synthetic fixtures only.
